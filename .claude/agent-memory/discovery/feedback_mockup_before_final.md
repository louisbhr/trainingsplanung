Before any UI requirement gets finalized, Louis wants to see an HTML mockup of the new screen (as with mockup-v3.html for the dashboard).

**Why:** Stated in Dashboard-v2 discovery (2026-09-24): "Bevor irgendetwas final festgezurrt wird, will er ein Mockup-HTML sehen." He judges layout/content choices visually, not from text.

**How to apply:** Mark UI requirements docs as ENTWURF until a mockup is approved; list the mockup as an explicit precondition for step 2 (approval). Keep the style of the previously approved mockup. Related: [[project-season-goals]].
